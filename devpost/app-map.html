A short guide to the Windows 11 Wi-Fi after sleep proof of concept. Open the project from its root with npm install and npm run dev, then visit http://localhost:3000.

Follow one answer

  1. src/app/page.tsx collects an answer and optional note, then calls submitAnswer. It renders the next question, evidence history, or final report.
  2. src/lib/flow.ts validates the choice, records exactly what the user reported, and chooses the next safe question or outcome. For “Neither device works,” it asks whether both devices were on the same Wi-Fi before treating the comparison as evidence.
  3. The same module's formatReport turns the observations into text for IT. An invalid comparison stays visible and labeled invalid.
  4. src/app/api/highlights/route.ts may ask Gemini which recorded evidence IDs to emphasize. It rejects unknown IDs and returns standard highlights when the key or service is unavailable. The model never chooses a diagnostic branch.

Try it

Use the sample issue. Choose “Neither device works,” then “No, different networks.” The app records that the comparison was invalid and offers one repeat. Finish a branch, copy the report, and check that the invalid observation remains. Try “Could not test” and “Stop and create report” to see how uncertainty is preserved.

The browser tab holds the case. There is no automatic inspection or repair. Do not enter passwords or private support data in the demo.

Checks

npm test covers the major branches. npm run build checks the production build. The GitHub Actions workflow also starts the production server and checks the page and fallback report API.
